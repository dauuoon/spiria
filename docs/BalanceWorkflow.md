# Balance Workflow

## 1. 관리 구조

Spiria의 게임 밸런스는 다음 세 계층으로 관리한다.

### docs

시스템의 목적과 규칙을 설명한다.

예시:

- 왜 마력이 필요한가
- 의뢰는 어떻게 생성되는가
- 탐사의 역할은 무엇인가
- 정령 제작 결과는 무엇을 보여주는가

### balance

실제 밸런스 수치의 원본이다.

기준 파일:

`balance/Spiria_Game_Balance_v1.0.xlsx`

### src/data

게임이 실행할 때 참조하는 TypeScript 데이터다.

---

## 2. 수정 흐름

밸런스 엑셀 수정  
→ 수식과 시뮬레이션 결과 확인  
→ 변경 내역 기록  
→ 확정된 수치를 src/data에 반영  
→ 게임 실행  
→ 플레이 테스트  
→ 문제 기록  
→ 엑셀 수치 재조정

---

## 3. 엑셀 시트 역할

| 시트 | 역할 |
|---|---|
| 00_Guide | 파일 사용법과 전체 구조 |
| 01_Player | 플레이어 레벨과 마력 |
| 02_Level | 필요 경험치, 누적 경험치, 레벨 컬러 |
| 03_Dungeon | 지역별 탐사 비용과 보상 |
| 04_Quest | 의뢰 난이도, 보상, 생성 규칙 |
| 05_Item | 재료 기본 정보 |
| 06_Drop | 지역별 재료 드랍 가중치와 확률 |
| 07_Spirit | 정령 등급과 성장 |
| 08_Recipe | 세 가지 재료 조합 규칙 |
| 09_Economy | 성장 속도와 경제 시뮬레이션 |
| 10_ChangeLog | 변경 이력과 테스트 결과 |

---

## 4.1 제작 비용 시트 관리 항목

정령 제작 레벨 구간 비용은 밸런스 원본 시트에 아래 항목으로 관리한다.

- 최소 레벨
- 최대 레벨
- 재료 1종당 필요 수량
- 선택 재료 종류 수
- 총 소모량

총 소모량은 가급적 수식으로 계산한다.

---

## 5. 편집 규칙

- 노란색 셀은 직접 수정하는 입력값이다.
- 계산 셀의 수식을 숫자로 덮어쓰지 않는다.
- 아직 결정하지 않은 값은 TBD로 유지한다.
- 테스트하지 않은 값을 Final로 표시하지 않는다.
- 변경할 때마다 ChangeLog를 작성한다.
- 한 번에 여러 시스템의 수치를 크게 변경하지 않는다.
- 변경 전과 변경 후의 플레이 결과를 비교한다.

---

## 6. 밸런스 테스트 순서

### 1단계: 기본 루프

- 탐사 1회에 걸리는 시간
- 의뢰 1개 완료에 필요한 탐사 횟수
- 정령 제작까지 걸리는 시간
- 마력 부족 시 불편 정도

### 2단계: 성장

- 초반 레벨업 속도
- 하루 평균 레벨 상승량
- 콘텐츠 해금 간격
- 중반 이후 정체 구간

### 3단계: 경제

- 골드 획득량
- 골드 소비량
- 특정 재료의 부족
- 희귀 재료의 체감 확률

### 4단계: 장기 플레이

- 일주일 플레이 후 진행 상태
- 반복 플레이 피로도
- 의뢰 다양성
- 도감 완성 속도

## 8. 코드 반영 규칙

다음과 같은 숫자를 컴포넌트 내부에 직접 작성하지 않는다.

잘못된 예:

```ts
player.exp += 25;
player.energy -= 1;
```

대신 `src/data`의 값을 가져와 사용한다. 수치 변경 시에는 엑셀 → 데이터 반영 → 코드 참조 순서를 따른다.
